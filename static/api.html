YOUR FIVE DEVICES, CONNECTED

Automatic screen time.

Install a collector once on each of your three Windows PCs and two Google Pixel phones. Each device keeps an offline queue and sends its activity to your private cloud API over HTTPS. No manual screen-time entries are needed.

Connect to your cloud dashboard

SimonSealsAPI can run on Cloudflare at https://simonsealsapi.dev. After deployment, sign in there and create a separate pairing for each device. Full deployment, backup, and installation steps are in CLOUD_SETUP.md in the project and release package. The local preview on this PC does not automatically connect your devices.

Three Windows PCs

In the cloud dashboard, choose Pair device → Windows PC, give it a unique name, and download its pairing file. On that PC, install Python 3.12+, extract SimonSealsAPI-windows.zip, then run:

powershell -NoProfile -ExecutionPolicy Bypass -File .\install_windows.ps1 -Config .\SimonSealsAPI-YOUR-DEVICE-ID.json

The installer starts a hidden collector and registers it to start at sign-in. It samples the foreground app every five seconds and syncs roughly every minute. Chrome is recorded as chrome.exe. Load the optional Chrome extension from the Windows ZIP to also see active website domains; it stores no paths, search terms, titles, or browsing history and skips incognito. Website time is part of Chrome app time. Lock screens, sleep gaps, and inactivity beyond five minutes are excluded.

Chrome website tracking

Load the chrome-extension folder from the Windows ZIP at chrome://extensions with Developer mode enabled. Open the extension, paste the same Windows pairing JSON, and approve the server connection. The extension observes the active tab domain in the focused Chrome window, queues sessions in this Chrome profile, and retries upload. The Chrome tabs permission is used to read the active tab URL; only its domain is saved. Pause tracking in the extension popup to stop collecting websites.

Two Google Pixels

Create a separate Android pairing for each phone. Install SimonSealsAPI.apk, import the phone's pairing JSON, and grant Usage Access in Android settings. Keep background usage allowed for SimonSealsAPI. The app reads Android's foreground-app usage events and requests background collection/sync approximately every 15 minutes; Android may delay jobs. Opening the app also syncs. Collection starts after pairing, and old usage history is not imported.

Pause collection in the app to stop recording. Revoking a pairing in the dashboard stops uploads. Force-stopping the Android app prevents background work until it is reopened. The companion app requires Android 10 or later and still needs verification on your physical phones.

Daily totals

Device totals add together. A separate elapsed-time total merges simultaneous use across devices. Sessions crossing midnight are split into their calendar days; the dashboard handles daylight-saving transitions. The journal groups automatic app and website sessions by device; website domains are detail within Windows Chrome time. Windows idle time and Android foreground app time are estimates and may differ from Digital Wellbeing.

API reference

The deployed dashboard API requires its login session. Each collector has a separate bearer key that can only upload its own screen sessions; it cannot read your data or manage devices.

Collector payload

Send Authorization: Bearer DEVICE_TOKEN and Content-Type: application/json. Up to 200 sessions fit in one request; maximum request size is 256 KiB. A device must reuse the same event ID and content when retrying. Empty batches act as heartbeats.

{
  "device_id": "your-paired-device-id",
  "events": [{
    "event_id": "a-stable-unique-id",
    "app": "chrome.exe",
    "started_at": "2026-09-23T10:00:00-04:00",
    "ended_at": "2026-09-23T10:01:00-04:00"
  }]
}

Chrome website sessions use the same shape with "type":"website" and a lowercase domain in app, such as example.com. They require a Windows pairing and are shown as a breakdown of Chrome time, not additional screen-time minutes.

The API acknowledges a full batch only after a database transaction succeeds. It retains receipt IDs even if an entry is deleted, preventing a retry from recreating it. Invalid or revoked keys return HTTP 401. Device IDs must match the key. Retries with altered session content are rejected.

Other activities

{
  "kind": "water", "value": 250,
  "started_at": "2026-09-23T09:00:00-04:00"
}

Valid activity kinds are water, work, gym, sleep, screen, and custom. Water values are millilitres; timed kinds require ended_at. Custom activities accept optional value and unit. ISO timestamps require a timezone. Day queries use minutes east of UTC for offset, or explicit start and end timestamps for daylight-saving transitions. The dashboard uses explicit boundaries.

On Cloudflare, /api/export returns up to 500 entries per page. Follow next_cursor using /api/export?cursor=... until it is null. The dashboard Export button combines pages automatically.

Your data

All device keys are private; make a separate pairing for each device. Exported JSON never includes keys. Your cloud database and local queues are not separately encrypted by SimonSealsAPI. Back up the database using the deployment guide. Disconnect a device by revoking its key, and pause or uninstall its collector to stop local recording.
